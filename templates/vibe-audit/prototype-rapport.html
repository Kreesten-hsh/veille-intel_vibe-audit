L'audit passif de l'application LeadFlow a identifié deux vulnérabilités d'importance élevée permettant l'extraction non authentifiée de données clients et l'exposition d'une clé d'intégration.

Vibe-Audit · Fiche Détaillée de Vulnérabilité & Remédiation
Application : LeadFlow SaaS · Réf : SEC-01
Gravité : Élevé Constat confirmé SEC-01 : Absence de Row Level Security (RLS) sur la table des commandes
supabase/schema:orders
1. Impact Métier & Conséquence
Fuite de données transactionnelles clients
La table orders est accessible en lecture directe sans filtrage par utilisateur. Tout visiteur non authentifié connaissant l'URL Supabase publique peut télécharger l'historique complet des commandes, adresses emails et montants encaissés.
2. Preuve Technique Reproductible
Requête curl passive non intrusive Statut : 200 OK
# Requête passive effectuée sans jeton utilisateur
curl -s "https://app.leadflow.io/rest/v1/orders?select=id,customer_email,amount" \
  -H "apikey: eyJhbGciOiJIUzI1NiIsInR5cCI***"

# Données sensibles retournées en clair (échantillon masqué) :
[
  { "id": "ord_812", "customer_email": "m.***@gmail.com", "amount": 4900 },
  { "id": "ord_813", "customer_email": "agence.***@pro.fr", "amount": 12900 }
]
# Constat : 142 enregistrements accessibles publiquement
3. Remédiation Immédiate
Correction proposée
Cible : Lovable / Bolt / Cursor / Supabase SQL Prompt prêt à coller
Dans la configuration de la base de données Supabase, active la politique Row Level Security (RLS) sur la table `orders`. Applique la politique stricte d'isolation suivante : ALTER TABLE orders ENABLE ROW LEVEL SECURITY; CREATE POLICY "Utilisateur consulte ses propres commandes" ON orders FOR SELECT USING (auth.uid() = user_id); CREATE POLICY "Utilisateur insère uniquement pour son compte" ON orders FOR INSERT WITH CHECK (auth.uid() = user_id); Valide que les requêtes anonymes sans jeton d'authentification sont désormais rejetées.
4. Critères de Validation Post-Correction
  • Test 1 : Exécuter à nouveau la commande curl ci-contre. Le serveur doit renvoyer un tableau vide [] ou une erreur 401 Unauthorized.
  • Test 2 : Se connecter sur l'interface avec un compte client : vérifier que ses commandes personnelles restent visibles sans interruption.
  • Re-contrôle : Éligible au protocole de contre-vérification J+14 (inclus sur demande après déploiement).
